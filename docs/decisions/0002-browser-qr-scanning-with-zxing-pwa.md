# Сканирование QR в браузере: PWA на React с библиотекой ZXing

## Контекст и постановка задачи

Контролёры работают на собственных смартфонах, ставить нативное приложение заказчик не хочет (CON-1). Скан должен распознаваться не дольше 1 с с 10 кадрами в секунду (REQ-FUNC-002), работать на Android и iOS (AS-2). Чем распознавать QR-код в браузере?

## Драйверы решения

* CON-1: без установки из магазинов приложений; CON-4: только открытые лицензии.
* REQ-FUNC-002 и REQ-PERF-002: скорость распознавания и общее время до решения.
* Поддержка Safari на iOS 16+ (AS-2).
* Главный технический риск проекта — REQ-POC-001.

## Рассмотренные варианты

* PWA + `@zxing/browser` (Apache 2.0)
* PWA + `jsQR` (Apache 2.0)
* PWA + встроенный Barcode Detection API
* Нативное приложение (React Native)

## Итог решения

Выбранный вариант: «PWA + `@zxing/browser`», потому что он работает во всех целевых браузерах, включая Safari на iOS, где Barcode Detection API отсутствует, и распознаёт повреждённые коды лучше `jsQR`. `jsQR` оставлен как запасной вариант (AS-5).

### Последствия

* Хорошо, потому что сканер открывается по ссылке и устанавливается на главный экран (REQ-INST-002).
* Хорошо, потому что одна кодовая база для Android и iOS.
* Плохо, потому что доступ к камере возможен только по HTTPS (CON-3) и с разрешения пользователя.
* Плохо, потому что производительность зависит от смартфона — нужен прототип до начала разработки (REQ-POC-001, задача функции F05).

### Подтверждение

Прототип в первой итерации на трёх устройствах (бюджетный Android, флагманский Android, iPhone): 95 % кодов 3×3 см распознаются за ≤ 1 с. Если требование не выполнено — ADR пересматривается со статусом `superseded`.

## Плюсы и минусы вариантов

### PWA + `@zxing/browser`

* Хорошо, потому что поддерживает iOS Safari и Android Chrome.
* Хорошо, потому что активно сопровождается, лицензия Apache 2.0.
* Нейтрально, потому что размер бандла около 120 КБ в gzip (кэшируется service worker).

### PWA + `jsQR`

* Хорошо, потому что маленький размер и простой API.
* Плохо, потому что хуже распознаёт коды на бликующих экранах телефонов.

### Barcode Detection API

* Хорошо, потому что аппаратное ускорение и нулевой размер библиотеки.
* Плохо, потому что недоступен в Safari на iOS — отсекающий критерий.

### Нативное приложение

* Хорошо, потому что лучшая скорость и работа с камерой.
* Плохо, потому что противоречит CON-1 и требует публикации в магазинах.

## Дополнительная информация

Затрагивает представления SDD 002-composition и 007-scanner-states. Связано с ADR-0006 (поведение при отсутствии связи).
