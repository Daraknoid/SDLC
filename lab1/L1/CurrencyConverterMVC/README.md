# Конвертер BYN → EUR (Вариант 1, C++, WinAPI, MVC с активной моделью)

Готовое приложение с графическим интерфейсом на чистом Win32 API (без сторонних
библиотек), реализующее вариант 1 задания и каркас **MVC с активной моделью**.

## Что уже готово
В архиве уже лежит собранный `CurrencyConverter.exe` — **просто запустите его
двойным кликом в Windows**, ничего дополнительно ставить не нужно (собран
статически, консоль не открывается).

## Оформление
Интерфейс сделан не на «голых» WinAPI-контролах, а стилизован:
- шрифт **Segoe UI** для всех надписей и полей;
- белая «карточка» со скруглёнными углами и тонкой рамкой на светлом фоне;
- разделение подпись/значение цветом (серая подпись, тёмное значение);
- строка результата выделена крупным зелёным жирным шрифтом;
- кастомная синяя кнопка «Ввод чисел» с закруглёнными углами (owner-draw);
- в окне ввода — такая же акцентная кнопка «OK» и контурная кнопка «Отмена»;
- подключён `app.manifest`, включающий современный стиль стандартных
  Windows-контролов (полей ввода и т.д.), а не старый вид Windows 95.

## Функциональность (по заданию)
- На главной форме — метки с последними введёнными числами и результатом конвертации.
- Кнопка **«Ввод чисел»** открывает окно для ввода суммы (BYN) и курса (BYN за 1 EUR).
- Последние введённые данные запоминаются и восстанавливаются при повторном открытии окна ввода.
- При некорректных данных (отрицательные числа, не число, пустое поле) — сообщение об ошибке.

## Структура проекта (соответствие MVC)

```
src/
 ├─ Model.h         — CurrencyModel: АКТИВНАЯ модель. Хранит данные и логику
 │                     конвертации, сама рассылает уведомления View через
 │                     интерфейс IModelObserver (паттерн "Наблюдатель").
 ├─ IController.h   — интерфейс, через который View обращается к Controller,
 │                     не зная его конкретной реализации.
 ├─ Controller.h/.cpp — AppController: обрабатывает клик по кнопке, открывает
 │                     окно ввода, передаёт данные в модель. Обновлением View
 │                     сам НЕ занимается — это делает модель.
 ├─ View.h/.cpp     — MainWindow: главное окно, реализует IModelObserver,
 │                     подписывается на модель и обновляет метки при
 │                     получении уведомления OnModelChanged().
 ├─ InputDialog.h   — вспомогательное модальное окно ввода данных.
 └─ main.cpp        — точка входа, связывает Model/View/Controller.
```

### Почему это "активная модель"
Модель (`CurrencyModel`) не пассивна: при вызове `SetData()` она сама
проверяет данные, сама вычисляет результат и **сама вызывает
`NotifyObservers()`**, оповещая View о необходимости перерисоваться.
View не спрашивает у модели данные "по требованию" контроллера — она
подписана на модель заранее (`model.AddObserver(this)`), и реагирует
на изменения самостоятельно, через `OnModelChanged()`.
Controller в этой схеме — только посредник между пользовательским вводом
и моделью, он не трогает элементы View напрямую.

## Как открыть и пересобрать проект в VS Code (пошагово)

### Шаг 1. Распакуйте архив
Распакуйте `CurrencyConverterMVC.zip` в удобную папку, например
`C:\Projects\CurrencyConverterMVC`.

### Шаг 2. Поставьте компилятор MinGW-w64 (если ещё не стоит)
Без него VS Code умеет только редактировать код, но не соберёт `.exe`.
Проще всего через **MSYS2**:
1. Скачайте и установите MSYS2: https://www.msys2.org/
2. Откройте **MSYS2 MINGW64** (не обычный MSYS2!) из меню Пуск и выполните:
   ```
   pacman -Syu
   pacman -S mingw-w64-x86_64-gcc
   ```
3. Добавьте компилятор в PATH Windows: найдите папку вида
   `C:\msys64\mingw64\bin` и добавьте её в переменную окружения `PATH`
   (Панель управления → Система → Дополнительные параметры системы →
   Переменные среды → `Path` → Добавить).
4. Проверьте в обычной командной строке (`cmd`): `g++ --version` — должна
   показаться версия компилятора, а не ошибка «не является командой».

*(Альтернатива MSYS2 — готовая сборка [WinLibs](https://winlibs.com/): скачать
архив, распаковать, добавить его `bin`-папку в PATH.)*

### Шаг 3. Откройте папку проекта в VS Code
`Файл → Открыть папку...` → выберите `CurrencyConverterMVC`.

### Шаг 4. Поставьте расширение C/C++
В VS Code откройте вкладку Extensions (`Ctrl+Shift+X`), найдите
**C/C++** (издатель Microsoft) и нажмите Install. Оно даёт подсветку,
автодополнение и подсказки по WinAPI.

### Шаг 5. Соберите проект
Нажмите `Ctrl+Shift+B` (Run Build Task). VS Code выполнит задачи из
`.vscode/tasks.json`:
1. `windres` скомпилирует `app.manifest` в ресурс (для красивых
   современных контролов);
2. `g++` соберёт всё в `CurrencyConverter.exe` в корне проекта.

Если всё прошло без ошибок, в корне папки появится (обновится)
`CurrencyConverter.exe`.

### Шаг 6. Запустите
Просто дважды кликните по `CurrencyConverter.exe` в проводнике Windows —
откроется окно приложения. Никакой консоли, никаких дополнительных
установок (флаг `-static` вшивает рантайм компилятора прямо в exe).

### Если меняли код
Каждый раз после правок жмите `Ctrl+Shift+B` — задача пересоберёт exe
заново, старый файл будет перезаписан.

### Сборка вручную из терминала (без задач VS Code)
Откройте терминал **MSYS2 MINGW64** (или обычный `cmd`/PowerShell, если
`g++` уже в PATH), перейдите в папку проекта и выполните:
```
windres src/resource.rc -O coff -o src/resource_res.o
g++ -O2 -mwindows -static -std=c++17 -municode src/main.cpp src/View.cpp src/Controller.cpp src/resource_res.o -o CurrencyConverter.exe
```

Ключи:
- `-mwindows` — приложение GUI, без консольного окна;
- `-static` — статическая линковка рантайма, exe запускается без доп. библиотек;
- `-municode` — использовать `wWinMain`/юникод-версии WinAPI функций;
- `resource_res.o` — скомпилированный манифест (современный стиль контролов).

## Для отчёта по лабораторной
- IDE: Visual Studio Code (+ расширение C/C++ от Microsoft, компилятор MinGW-w64).
- Язык: C++ (объектно-ориентированный, классы Model/View/Controller).
- Отладка: точки останова в VS Code через конфигурацию `launch.json` (при
  необходимости можно добавить, используя отладчик `gdb`, который идёт в
  комплекте MinGW-w64) — продемонстрируйте останов в `CurrencyModel::SetData`.
- Для пункта про SysMLv2/UML в VS Code можно установить расширения
  `PlantUML` (для UML-диаграмм классов Model/View/Controller) — постройте
  диаграмму классов по структуре проекта выше и вставьте в отчёт.
